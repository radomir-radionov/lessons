## 1. Введение в npm и Node.js

### Зачем фронтенд-разработчику Node.js

До сих пор мы писали HTML и CSS вручную и открывали файлы в браузере. Этого достаточно для простых страниц. Но когда проект растёт, появляются задачи:

- Компилировать Sass в CSS
- Объединять несколько CSS-файлов в один
- Оптимизировать код для продакшена
- Устанавливать библиотеки (иконки, фреймворки)

Для этого нужны **инструменты сборки**. Они работают через **Node.js** — среду выполнения JavaScript вне браузера (в терминале).

### Node.js

**Node.js** — программа, которая позволяет запускать JavaScript на компьютере (не в браузере). Устанавливается с [nodejs.org](https://nodejs.org/) (версия LTS).

Проверка установки:

```bash
node --version
# v20.x.x

npm --version
# 10.x.x
```

### npm — Node Package Manager

**npm** — менеджер пакетов для Node.js. Устанавливается вместе с Node.js. Через npm можно:

- Устанавливать библиотеки и инструменты (`npm install parcel`)
- Инициализировать проект (`npm init`)
- Запускать скрипты (`npm start`)

### Инициализация проекта

```bash
mkdir my-project
cd my-project
npm init -y
```

Флаг `-y` — принять значения по умолчанию. Создаётся файл **`package.json`** — «паспорт» проекта.

### Структура package.json

```json
{
  "name": "my-project",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC"
}
```

| Поле | Назначение |
| ---- | ---------- |
| `name` | Имя проекта |
| `version` | Версия |
| `scripts` | Команды для `npm run` |
| `dependencies` | Пакеты, нужные в продакшене |
| `devDependencies` | Пакеты только для разработки (сборщики, линтеры) |

### Установка пакетов

```bash
# Dev-зависимость (только для разработки)
npm install --save-dev parcel

# Обычная зависимость
npm install lodash
```

После установки:

- Появляется папка **`node_modules/`** — все установленные пакеты
- `package.json` обновляется: пакет попадает в `dependencies` или `devDependencies`

### .gitignore

Папку `node_modules/` **не коммитят** в Git — она огромная. Добавь в `.gitignore`:

```
node_modules/
dist/
.parcel-cache/
```

---

### Определения и понятия

#### Node.js

**Node.js** — среда выполнения JavaScript вне браузера. Позволяет запускать JS-скрипты в терминале и использовать инструменты сборки.

#### npm (Node Package Manager)

**npm** — менеджер пакетов для Node.js. Устанавливает библиотеки, управляет зависимостями проекта, запускает скрипты.

#### package.json

**package.json** — JSON-файл с метаданными проекта: имя, версия, зависимости, скрипты. Создаётся командой `npm init`.

#### node_modules

**node_modules** — папка, в которую npm устанавливает все зависимости проекта. Не коммитится в Git.

#### Зависимость (dependency)

**Зависимость** — внешний пакет (библиотека или инструмент), который проект использует. Записывается в `package.json`.

#### devDependencies

**devDependencies** — зависимости, нужные только на этапе разработки (сборщики, тесты). Не попадают в финальную сборку для пользователя.

## 2. Введение в Sass

### Что такое CSS-препроцессор

**CSS-препроцессор** — инструмент, который расширяет возможности CSS. Ты пишешь код на **Sass** (файл `.scss`), а сборщик (Parcel) **компилирует** его в обычный CSS, который понимает браузер.

### Зачем нужен Sass

| Возможность | CSS | Sass |
| ----------- | --- | ---- |
| Переменные | `var(--color)` (CSS Custom Properties) | `$color: #2563eb;` |
| Вложенность | Писать каждый селектор отдельно | `.header { .logo { } }` |
| Импорты | `@import` (медленный) | `@import 'file'` (partials) |
| Функции | Ограниченные | `darken()`, `lighten()` и др. |

На этом уроке изучаем **переменные** и **вложенность**. Миксины и функции — в продвинутом Sass.

### Синтаксис SCSS

Мы используем синтаксис **SCSS** (Sassy CSS) — он похож на обычный CSS с фигурными скобками:

```scss
// Это комментарий в Sass

$primary-color: #2563eb;

.button {
  background-color: $primary-color;
  padding: 12px 24px;

  &:hover {
    background-color: darken($primary-color, 10%);
  }
}
```

Компилируется в:

```css
.button {
  background-color: #2563eb;
  padding: 12px 24px;
}

.button:hover {
  background-color: #1d4ed8;
}
```

### Подключение в HTML

С Parcel достаточно указать `.scss` в `<link>`:

```html
<link rel="stylesheet" href="styles.scss" />
```

Parcel автоматически компилирует Sass при запуске dev-сервера.

---

### Определения и понятия

#### Sass (Syntactically Awesome Style Sheets)

**Sass** — CSS-препроцессор, расширяющий возможности CSS: переменные, вложенность, импорты, функции. Компилируется в обычный CSS.

#### SCSS

**SCSS** — синтаксис Sass, максимально похожий на CSS (фигурные скобки, точки с запятой). Файлы имеют расширение `.scss`.

#### Препроцессор

**Препроцессор** — программа, которая обрабатывает код до его использования. Sass-препроцессор превращает `.scss` в `.css`.

#### Компиляция

**Компиляция** — преобразование исходного кода (Sass) в целевой формат (CSS), понятный браузеру.

## 3. Переменные и вложенность

### Переменные

В Sass переменные объявляются через **`$`**:

```scss
$primary-color: #2563eb;
$text-color: #1f2937;
$font-family: 'Segoe UI', sans-serif;
$spacing: 16px;
$border-radius: 8px;
```

Использование:

```scss
body {
  color: $text-color;
  font-family: $font-family;
}

.card {
  padding: $spacing;
  border-radius: $border-radius;
  border: 1px solid lighten($text-color, 60%);
}
```

**Преимущество:** изменил цвет в одном месте — обновился везде.

### Вложенность селекторов

В CSS:

```css
.header { }
.header__logo { }
.header__nav { }
.header__nav a { }
.header__nav a:hover { }
```

В Sass:

```scss
.header {
  background-color: $primary-color;
  padding: 16px;

  &__logo {
    font-weight: bold;
  }

  &__nav {
    a {
      color: white;
      text-decoration: none;

      &:hover {
        text-decoration: underline;
      }
    }
  }
}
```

### Символ `&` (амперсанд)

**`&`** — ссылка на **родительский селектор**. Используется для:

- Псевдоклассов: `&:hover`, `&:focus`
- Псевдоэлементов: `&::before`
- БЭМ-модификаторов: `&--active`, `&__element`
- Составных селекторов: `&.is-open`

```scss
.btn {
  background: $primary-color;

  &:hover {
    background: darken($primary-color, 10%);
  }

  &--large {
    padding: 16px 32px;
  }

  &.is-disabled {
    opacity: 0.5;
    pointer-events: none;
  }
}
```

### Partials (частичные файлы)

Для организации большого проекта стили разбивают на файлы:

```
styles/
├── _variables.scss
├── _base.scss
├── _header.scss
├── _cards.scss
└── main.scss
```

- Файлы partials начинаются с **`_`**
- В `main.scss` — импорты:

```scss
@import 'variables';
@import 'base';
@import 'header';
@import 'cards';
```

> В `@import` не указывай `_` и расширение `.scss` — Sass найдёт `_variables.scss` по имени `variables`.

---

### Определения и понятия

#### Sass-переменная

**Sass-переменная** — именованное значение (`$name: value`), которое можно переиспользовать в стилях. Объявляется один раз, меняется в одном месте.

#### Вложенность (nesting)

**Вложенность** — возможность Sass писать дочерние селекторы внутри родительского блока. Уменьшает повторение и улучшает читаемость.

#### `&` (амперсанд)

**`&`** — в Sass ссылается на родительский селектор. Позволяет писать `&:hover` вместо полного пути `.btn:hover`.

#### Partial (частичный файл)

**Partial** — Sass-файл, который не компилируется отдельно, а подключается через `@import`. Имя начинается с `_`: `_variables.scss`.

#### `@import`

**`@import`** — директива Sass для подключения partial-файлов в главный файл стилей.

## 4. Сборщик Parcel

### Что такое сборщик (bundler)

**Сборщик** — инструмент, который:

1. Компилирует Sass → CSS
2. Объединяет файлы
3. Оптимизирует код (минификация)
4. Запускает локальный dev-сервер с автообновлением

Мы используем **Parcel** — простой сборщик с нулевой конфигурацией.

### Установка

```bash
npm install --save-dev parcel
```

### Скрипты в package.json

```json
{
  "scripts": {
    "start": "parcel index.html",
    "build": "parcel build index.html"
  }
}
```

### Запуск dev-сервера

```bash
npm start
# или
npx parcel index.html
```

Parcel:

- Откроет страницу в браузере
- Запустит локальный сервер (обычно `http://localhost:1234`)
- При сохранении `.scss` — автоматически перекомпилирует и обновит страницу

### Продакшен-сборка

```bash
npm run build
# или
npx parcel build index.html
```

Создаётся папка **`dist/`** с оптимизированными файлами — их можно загрузить на хостинг.

```
dist/
├── index.html
├── styles.abc123.css   ← скомпилированный и минифицированный CSS
└── ...
```

### Структура проекта

```
sass-project/
├── index.html
├── package.json
├── package-lock.json
├── styles.scss
├── .gitignore
├── node_modules/       ← не коммитить
├── dist/               ← результат сборки, не коммитить
└── .parcel-cache/      ← кэш Parcel, не коммитить
```

---

### Определения и понятия

#### Parcel

**Parcel** — сборщик проектов (bundler) с нулевой конфигурацией. Компилирует Sass, запускает dev-сервер, собирает продакшен-версию.

#### Сборщик (bundler)

**Сборщик** — инструмент, который обрабатывает исходные файлы проекта (Sass, JS, изображения) и создаёт готовые файлы для браузера.

#### Dev-сервер

**Dev-сервер** — локальный веб-сервер для разработки. Автоматически перекомпилирует код и обновляет страницу при сохранении.

#### `dist/` (distribution)

**`dist/`** — папка с финальной сборкой проекта, готовой для деплоя на хостинг. Создаётся командой `parcel build`.

#### `npx`

**`npx`** — утилита npm для запуска пакетов без глобальной установки. `npx parcel index.html` запускает Parcel из `node_modules`.

#### package-lock.json

**package-lock.json** — файл, фиксирующий точные версии установленных пакетов. Создаётся автоматически при `npm install`. Коммитится в Git.
