## 1. Введение: зачем нужен Git

Без контроля версий файлы множатся: `index-v2.html`, `index-final.html`, `index-FINAL-FINAL.html` — и непонятно, какая версия актуальная.

**VCS (Version Control System)** записывает историю изменений и позволяет вернуться к любой версии.

### Аналогия

| Образ            | В проекте                              |
| ---------------- | -------------------------------------- |
| Страницы книги   | Файлы (`index.html`, `style.css`)      |
| Издание книги    | Коммит с датой и описанием             |
| Git              | Библиотекарь, хранящий все издания     |
| GitHub           | Онлайн-библиотека для других людей     |

### Git и GitHub — не одно и то же

|                | Git                          | GitHub                              |
| -------------- | ---------------------------- | ----------------------------------- |
| **Что это**    | Программа на компьютере      | Сайт в интернете                    |
| **Где**        | Локально, в терминале        | В облаке                            |
| **Зачем**      | История изменений            | Хранить код онлайн, делиться        |
| **Интернет?**  | Нет (для локальных коммитов) | Да (для push/pull)                  |

> Git работает и без GitHub. GitHub — популярный способ хранить и показывать код в интернете.

### Ключевые понятия

| Термин            | Определение                                              |
| ----------------- | -------------------------------------------------------- |
| **VCS**           | Система контроля версий — история изменений в проекте    |
| **Git**           | Распределённая VCS; работает локально, быстрая         |
| **Репозиторий**   | Папка проекта с историей (скрытая папка `.git`)          |
| **Коммит**        | Сохранённый «снимок» проекта с сообщением и датой        |
| **GitHub**        | Веб-сервис для хостинга Git-репозиториев                 |

## 2. Установка и настройка Git

### Проверить установку

Открой терминал в VS Code: **Terminal → New Terminal** (`` Ctrl + ` `` / `` Cmd + ` ``).

```bash
git --version
```

Если команда не найдена — установи Git с [git-scm.com](https://git-scm.com/) и перезапусти VS Code.

### Настроить имя и email (один раз)

```bash
git config --global user.name "Твоё Имя"
git config --global user.email "твой@email.com"
```

> Используй тот же email, что при регистрации на GitHub.

Проверить:

```bash
git config --global user.name
git config --global user.email
```

### Инициализировать репозиторий

```bash
cd ~/Documents/my-first-site
git init
```

```
Initialized empty Git repository in /Users/you/my-first-site/.git/
```

Появилась скрытая папка `.git` — **не удаляй и не редактируй её вручную**.

```bash
git status
```

| Команда       | Назначение                                      |
| ------------- | ----------------------------------------------- |
| `git init`    | Превращает папку в репозиторий (один раз)       |
| `git status`  | Показывает состояние: ветка, изменённые файлы   |
| `.git`        | Служебная папка с историей (скрыта)             |
| `main`        | Имя основной ветки (проверить: `git branch`)    |

## 3. Основной цикл Git: add, commit, status

### Три состояния файла

```
Modified  ──git add──►  Staged  ──git commit──►  Committed
   ▲                                              │
   └──────────── редактирование файла ────────────┘
```

| Состояние   | Описание                                           |
| ----------- | -------------------------------------------------- |
| **Modified**| Файл изменён, но не подготовлен к коммиту         |
| **Staged**  | Файл добавлен через `git add`, готов к коммиту     |
| **Committed**| Файл сохранён в истории                           |

### `git add` — подготовка

```bash
git add index.html       # один файл
git add .                # все изменения в папке
```

### `git commit` — сохранение

```bash
git commit -m "Добавлена главная страница"
```

**Хорошие сообщения:** `"Добавлена главная страница"`, `"Подключены стили CSS"`.  
**Плохие:** `"fix"`, `"изменения"`, `"asdfgh"`.

### Полный цикл

```bash
# 1. Измени файл и сохрани (Cmd+S / Ctrl+S)
git status
git add index.html style.css
git commit -m "Добавлены HTML и CSS"
git status    # → nothing to commit, working tree clean
```

### Пример: три коммита

```bash
git add index.html
git commit -m "Создана HTML-страница"

git add style.css
git commit -m "Добавлены базовые стили"

git add images/
git commit -m "Добавлены изображения"
```

| Термин              | Определение                                        |
| ------------------- | -------------------------------------------------- |
| **Staging area**    | Промежуточная зона между файлами и коммитом        |
| **Working directory**| Рабочая папка, где ты редактируешь файлы          |
| **Untracked**       | Файл, который Git ещё не отслеживает (красный в `git status`) |

## 4. История изменений: `git log` и `.gitignore`

### `git log`

```bash
git log                  # полная информация
git log --oneline        # компактный вид (рекомендуется)
git log --oneline -3     # последние 3 коммита
```

```
a1b2c3d Добавлены изображения
e4f5g6h Добавлены базовые стили
i7j8k9l Создана HTML-страница
```

Самый свежий коммит — сверху. Хеш (`a1b2c3d`) — уникальный идентификатор.

### `.gitignore`

Не все файлы нужно хранить в Git: системные (`.DS_Store`), кэш, секреты.

```gitignore
# Системные файлы
.DS_Store
Thumbs.db

# Папки редакторов
.vscode/
.idea/

# Зависимости
node_modules/

# Временные файлы
*.log
*.tmp
```

```bash
git add .gitignore
git commit -m "Добавлен .gitignore"
```

> Файлы, уже закоммиченные до `.gitignore`, останутся в истории. Убрать: `git rm --cached <файл>`.

| Паттерн    | Значение                    |
| ---------- | --------------------------- |
| `file.txt` | Конкретный файл             |
| `*.log`    | Все файлы с расширением     |
| `folder/`  | Вся папка                   |
| `# текст`  | Комментарий                 |

## 5. GitHub: удалённый репозиторий и push

### Зачем GitHub

- **Портфолио** — работодатели видят проекты
- **Резервная копия** — код не потеряется
- **Доступ** — можно работать с любого устройства
- **Команда** — совместная разработка

### Создать репозиторий

1. Зарегистрироваться на [github.com](https://github.com)
2. **+** → **New repository**
3. Имя: `my-first-site`, **Public**, **без** README и `.gitignore`
4. **Create repository**

### Подключить и отправить

```bash
git remote add origin https://github.com/твой-username/my-first-site.git
git remote -v
git push -u origin main
```

| Команда                          | Назначение                              |
| -------------------------------- | --------------------------------------- |
| `git remote add origin <url>`    | Подключить удалённый репозиторий        |
| `git remote -v`                  | Показать список remote с URL            |
| `git push -u origin main`        | Первый push (запоминает связь)          |
| `git push`                       | Последующие отправки                    |

> При первом push GitHub может попросить **Personal Access Token** вместо пароля: Settings → Developer settings → Personal access tokens.

### Полная последовательность

```bash
# Локально
git init
git add .
git commit -m "Первый коммит"

# Подключение к GitHub
git remote add origin https://github.com/username/repo.git
git push -u origin main

# При следующих изменениях
git add .
git commit -m "Описание изменений"
git push
```

## Словарь терминов

| Термин              | Краткое определение                              |
| ------------------- | ------------------------------------------------ |
| VCS                 | Система контроля версий                          |
| Git                 | Распределённая система контроля версий           |
| GitHub              | Веб-сервис для хостинга репозиториев             |
| Репозиторий (repo)  | Папка проекта с историей (`.git`)                |
| Коммит (commit)     | Сохранённый снимок проекта с сообщением          |
| Ветка (branch)      | Независимая линия разработки (`main`)            |
| `git init`          | Инициализация репозитория                        |
| `git add`           | Добавление файлов в staging area                 |
| `git commit`        | Создание коммита                                 |
| `git status`        | Текущее состояние репозитория                    |
| `git log`           | История коммитов                                 |
| Staging area        | Область подготовки перед коммитом                |
| `.gitignore`        | Список игнорируемых файлов                       |
| Remote (origin)     | Удалённый репозиторий на сервере                 |
| `git push`          | Отправка коммитов на удалённый сервер            |
| Хеш коммита         | Уникальный идентификатор коммита                 |
| PAT                 | Personal Access Token — ключ для GitHub          |
